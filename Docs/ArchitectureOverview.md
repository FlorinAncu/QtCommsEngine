ArchitectureOverview.md
=========================================

QtCommsEngine is a modular communication runtime designed with strict separation of concerns, deterministic behavior and robust error handling. The architecture is organized into four major layers: Transport Layer, Runtime Layer, Protocol Layer and Infrastructure Layer. Each layer has clearly defined responsibilities and interacts with the others through stable Qt‑based interfaces.

The Transport Layer contains CommChannel, TcpChannel and MockChannel. CommChannel is the abstract interface that defines the basic operations required for any transport, including opening and closing the connection, checking connection state, sending raw binary buffers and receiving raw binary buffers. TcpChannel implements real TCP communication using QTcpSocket. It manages connection establishment, disconnection, blocking send and receive operations, timeout handling and error reporting. MockChannel provides deterministic in‑memory transport for testing. It stores the last sent buffer and returns predefined responses without performing any network I/O. This layer is responsible for all platform‑specific communication details.

The Runtime Layer contains CommManager and CommClient. CommManager controls the connection lifecycle and provides a unified interface for sending and receiving messages through the underlying transport. It ensures that all transport operations are serialized and protected by mutexes. CommClient extends CommManager and implements the high‑level communication engine. It provides automatic reconnection, retry logic, heartbeat, protocol resynchronization and a dedicated sender thread implemented using QThread. CommClient uses MessageQueue to manage prioritized message dispatching and ensures that protocol‑critical messages such as heartbeat or version negotiation are processed with higher priority.

The Protocol Layer contains Message, MessageBuilder, MessageParser, ProtocolVersion, ProtocolCompatibility, ProtocolValidator, BinaryProtocolSerializer and Crc32. This layer defines the binary protocol used by QtCommsEngine. Messages are represented by an integer identifier and a QByteArray payload. MessageBuilder constructs well‑known protocol messages. MessageParser extracts message identifiers and payloads from raw binary buffers. BinaryProtocolSerializer converts Message objects into binary frames and reconstructs Message objects from binary frames. ProtocolValidator ensures that messages conform to protocol rules. ProtocolVersion defines the protocol version constant. ProtocolCompatibility checks whether two protocol versions are compatible or whether fallback is possible. Crc32 computes CRC32 checksums for integrity validation. This layer is responsible for serialization, deserialization, validation and versioning.

The Infrastructure Layer contains Logger, ErrorCode, ErrorHandler, ResponseHandler and RetryPolicy. Logger provides simple logging functions using Qt types. ErrorCode enumerates common error identifiers. ErrorHandler logs error codes and provides basic error processing. ResponseHandler interprets server responses and maps them to ErrorCode. RetryPolicy defines retry configuration fields such as maximum number of retries, retry delay and reconnect delay. This layer provides cross‑cutting utilities used throughout the runtime and protocol layers.

The data flow begins when the application enqueues a Message into CommClient. The message is stored in MessageQueue with priority. The sender thread pops the next message and serializes it using BinaryProtocolSerializer. CommManager ensures that the connection is active and that transport operations are protected by mutexes. The serialized binary buffer is sent through CommChannel. The transport receives the response, which is parsed and validated by MessageParser and ProtocolValidator. ResponseHandler interprets the result and CommClient returns success or failure to the application.

QtCommsEngine is designed for extensibility. New transports such as SerialChannel or UdpChannel can be added by implementing CommChannel. New message types and protocol versions can be introduced by extending MessageBuilder and ProtocolVersion. Custom logging and error handling can be integrated by replacing Logger and ErrorHandler. The architecture is fully modular and suitable for industrial communication systems.
